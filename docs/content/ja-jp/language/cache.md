# キャッシュ（cache）

`GET` と `QUERY` のエンドポイントは、`.comat` に `cache` を書くと、レスポンスをローカルにキャッシュできます。**クライアントもサーバも**、同じ 1 行で動きます。

```comat
// user/get_ping.comat
cache 60000          // 60 秒だけ、メモリにキャッシュする
```

| 書き方 | 意味 |
|---|---|
| （書かない） | キャッシュしない |
| `cache off` | 強制的にキャッシュしない |
| `cache 5000` | 5000 ミリ秒（ttl）だけ、**メモリ**にキャッシュする |
| `cache 5000 cookie` | 5000 ミリ秒だけ、**cookie** にキャッシュする（**クライアントのみ**） |

- 対象は `get` と `query` のエンドポイントだけです。ほかのメソッドに `cache`（`cache off` 以外）を書くとエラーになります。
- **`defaults.comat` と `init.comat` に書くと警告が出て、無視されます。** キャッシュはエンドポイントごとに、意図して決めるものだからです。
- ttl は 1 以上のミリ秒です。cookie の ttl は秒単位なので、1000 ミリ秒未満は 1 秒に切り上げます（警告が出ます）。
- キャッシュするのは **2xx のレスポンスだけ**です。`Set-Cookie` を伴うレスポンスはキャッシュしません。エラー（4xx / 5xx）もキャッシュしません。

## どのリクエストが「同じ」になるか

| | キー |
|---|---|
| **サーバ**（メモリ） | リクエストの**完全一致**: メソッド・path・クエリ・**全ヘッダ**（Cookie と Authorization を含む）・ボディ |
| **クライアント**（メモリ / cookie） | メソッド・URL（path とクエリ）・ボディ、と、`.comat` に**宣言したリクエストヘッダ**（`header` / `headerReq`）。ラッパーや init が足すヘッダ（Authorization など）は含めない |

クライアントはヘッダに関しての条件を少しゆるめてあります。毎回変わる値（トークンの更新、`User-Agent` など）でキャッシュが外れないようにするためです。

## 動作

- **サーバ**は、ラッパーを通る**前に**キャッシュを引きます。当たれば、ラッパーもハンドラも動かさずに、保存した応答を返します。認証のヘッダ・cookie もキーに入るので、別のユーザーの応答が返ることはありません（ただし、セッションが失効しても ttl の間は、同じ認証情報のリクエストに保存した応答が返ります）。
- **クライアント**は、ラッパーを通った後、通信の直前に引きます。当たれば通信しません（ラッパーは動きます）。
- メモリのキャッシュは、プロセスごとです（複数のサーバのプロセスで共有しません）。最大 1000 件で、超えたら古いものから捨てます。
- クライアントのキャッシュは、ログアウトなどのときに捨てられます: `c.clearCache()`（TypeScript）、`c.ClearCache()`（Go）、`c.clear_cache()`（Python）、`c::clear_cache()`（Rust）、`C.clearCache()`（Java / Kotlin の `CK`）、`C.clearCache()`（Swift）、`Comatype::C.clear_cache`（Ruby）、`C.ClearCache()`（C#）。

## cookie にキャッシュする（クライアントのみ）

`cache 5000 cookie` では、レスポンスを cookie に書きます。クライアントの cookie の置き場（ブラウザなら `document.cookie`、それ以外は cookie jar）に、`comatype_cache_<ハッシュ>` という名前で保存し、期限は `Max-Age` です。

- cookie jar を渡していないクライアント（ブラウザ以外）では、キャッシュしません。
- cookie には大きさの上限（1 つ約 4KB）があるので、符号化した値が 3800 文字を超えるレスポンスは、キャッシュしません。
- `comatype_cache_` で始まる cookie は、サーバへ送り返しません（jar を使うクライアント）。**ブラウザは、同じ origin のリクエストに cookie を自動で付けるので、キャッシュの cookie もサーバへ送られます**（`httpOnly` にもできません）。
- サーバは、`cookie` のキャッシュを使いません（`cache 5000 cookie` のエンドポイントでも、サーバ側はキャッシュしません）。
