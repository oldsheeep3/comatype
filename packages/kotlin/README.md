# comatype-ktx for Kotlin

Comatype runtime for Kotlin: a coroutine (`suspend`) client and server on top of the Java runtime. Data classes and sealed interfaces; no kotlinx.coroutines needed.

[Maven Central](https://central.sonatype.com/artifact/net.sheeplab.comatype/comatype-ktx) · [Documentation](https://comatype.sheeplab.net) · [GitHub](https://github.com/oldsheeep3/comatype)

> Comatype: write an API once in `.comat` files, get types, validation, a client and a server in nine languages.
> This package is the **Kotlin** runtime that the generated code depends on.

## How to use

### Install

```kotlin
// Gradle (Kotlin DSL)
dependencies {
    implementation("net.sheeplab.comatype:comatype-ktx:0.0.2")   // brings net.sheeplab.comatype:comatype
}
```

JDK 21 or later. Types, validation, cookies and endpoints come from the Java runtime `net.sheeplab.comatype:comatype`; this artifact adds the coroutine `CK` client and `coGet` / `coPut` ... handlers. Generated code goes to `<root>/src/main/kotlin/comatype/gen/` by default (set `package` on the target to change it).

The `comatype` command (parser, checker and generators) is separate from the runtime:

```bash
curl -fsSL https://raw.githubusercontent.com/oldsheeep3/comatype/main/install.sh | sh
```

This downloads the prebuilt `comatype` command (and its short alias `comat`) for macOS (arm64, x64) and Linux (x64, arm64) from the [latest release](https://github.com/oldsheeep3/comatype/releases/latest); no Rust toolchain needed. On Windows, download `comatype-x86_64-pc-windows-msvc.zip` from the release page. To build it from source instead: `cargo install --git https://github.com/oldsheeep3/comatype comatype-cli`.

### Import

```kotlin
import comatype.ktx.CK                // suspend client: CK.get / CK.put / CK.init ...
import comatype.ktx.coPut             // suspend server handlers: coGet / coPost / coPut ...
import comatype.ktx.CWrap             // client wrapper type
import comatype.ktx.SWrap             // server wrapper type
import comatype.S                     // the server
import comatype.CookieJar

import comatype.gen.Types             // generated: named types
import comatype.gen.Init              // generated: wrappers, ctx, wrapper statuses
import comatype.gen.UserPutId         // generated: one object per .comat file
```

### Format / Lint

Generated files start with `// Code generated by comatype generate. DO NOT EDIT.` and carry `@file:Suppress(...)`. Exclude them from ktlint / detekt:

```kotlin
// build.gradle.kts with Spotless
spotless {
    kotlin {
        target("src/**/*.kt")
        targetExclude("src/main/kotlin/comatype/gen/**")
        ktlint()
    }
}
```

```yaml
# detekt.yml
build:
  excludes: ["**/comatype/gen/**"]
```

### Check

```bash
comatype check                  # check every .comat file; prints [error] / [warn] / [info] lines, exits 1 on errors
comatype check cache            # only one topic: cache, path, wrap, cookie, status, import, type
comatype endpoints -g           # list the endpoints, grouped by wrapper chain
comatype generate --lang kotlin # generate the code (kotlin only)
```

Run `comatype check` in CI so that a broken `.comat` never reaches the generated code.

### init.comat

`init.comat` holds the settings of the whole project. Put exactly one directly under `comatDir`.

```comat
// comatfiles/init.comat
import UserData from ../types/UserData.comat
import ApiError from ../types/common.comat

// The base url of every endpoint. Override it at run time with the COMATYPE_BASE_URL environment variable
baseUrl https://api.example.com

// The cookie the server issues (for `cookie on` endpoints)
cookie session {
    httpOnly: true,
    secure: true,
    sameSite: lax,
}

// A wrapper: what it adds to `ctx`, and the statuses it can return. You implement it in Kotlin
wrapper auth {
    ctx {
        user: UserData,
    }
    s401 ApiError
}
```

### comatfiles

A `.comat` file is one endpoint. Its method and path come from where the file is and what it is called.

```text
comatfiles/
├─ init.comat               baseUrl, cookie, wrapper declarations (exactly one)
├─ defaults.comat           defaults for this directory and below: wrap, headers, shared statuses
├─ post_user.comat          POST /user
└─ user/
   ├─ [id]/put.comat        PUT /user/:id        ([id] is a dynamic segment)
   ├─ (noauth)/             a group: not part of the path
   │  ├─ defaults.comat     wrap auth off
   │  ├─ post_login.comat   POST /user/login
   │  └─ get_ping.comat     GET /user/ping
   └─ get.comat             GET /user
types/                      types shared by endpoints (outside comatDir)
```

`comatype.config.json` says where `comatfiles` is and what to generate:

```json
{
  "$schema": "https://raw.githubusercontent.com/oldsheeep3/comatype/main/schema/comatype.config.schema.json",
  "services": {
    "api": {
      "comatDir": "./comatfiles",
      "targets": [{ "lang": "kotlin", "role": "client", "root": "./server" }]
    }
  }
}
```

See the [syntax reference](https://comatype.sheeplab.net/language/endpoint/) for `params`, `search`, `body`, headers, status codes and `path`.

## Example

### ComatFiles

```comat
// types/UserData.comat
UserData {
    name: string,
    email: email,
    phone: phone,
    uid: uuidv4,
}
```

```comat
// comatfiles/user/[id]/put.comat  ->  PUT /user/:id
import UserData from ../../../types/UserData.comat
import ApiError from ../../../types/common.comat

params {
    id: uuidv4,
}

body UserData

s200 UserData
s404 ApiError
```

```comat
// comatfiles/defaults.comat: applies to every endpoint below
import ApiError from ../types/common.comat

wrap auth        // the wrapper declared in init.comat
cookie on        // send and receive the session cookie
s500 ApiError    // every endpoint can answer 500
```

```comat
// comatfiles/user/(noauth)/defaults.comat: this group needs no login
wrap auth off
```

```comat
// comatfiles/user/(noauth)/post_login.comat  ->  POST /user/login
import ApiError from ../../../types/common.comat

body {
    email: email,
    password: string,
}

s200 {
    uid: uuidv4,
}
// the auth wrapper is off in this group, so declare the 401 yourself
s401 ApiError
```

Generate the Kotlin code with `comatype generate --lang kotlin`.

### Client

```kotlin
import comatype.ktx.CK
import comatype.gen.Types
import comatype.gen.UserPutId

suspend fun putUser(id: java.util.UUID, user: Types.UserData) {
    val res = CK.put(UserPutId.ENDPOINT, UserPutId.Request(params = UserPutId.Params(id), body = user))

    when (res) {
        is UserPutId.S200 -> res.body   // UserData (res.headers is S200Headers)
        is UserPutId.S404 -> res.body   // ApiError
        else -> {}
    }
}
```

`CK.get` / `CK.put` ... are suspend functions on `HttpClient.sendAsync` (they do not block a thread). A status that is not in the `.comat` throws `ComatypeException.UnexpectedStatus`.

### Server

```kotlin
import comatype.S
import comatype.gen.Types
import comatype.gen.UserPutId
import comatype.ktx.coPut

val s = S()

s.coPut(UserPutId.ENDPOINT) { req ->
    val user = db.user.update(req.params.id, req.body)
        ?: return@coPut S.Reply.of<UserPutId.Response>(UserPutId.S404(Types.ApiError("not_found", "user not found")))
    S.Reply.of<UserPutId.Response>(UserPutId.S200(user, UserPutId.S200Headers(xResourceVersion = "v2")))
}

s.serve("127.0.0.1", 3000)
```

Synchronous handlers use `s.get` / `s.put`. `s.handle(...)` fits any framework.

### Wrapper & Cookie

A wrapper wraps the request and the response: authentication, headers, logging. Declare it in `init.comat`, enable it with `wrap auth` in a `defaults.comat` or in an endpoint, and implement it in Kotlin.

```kotlin
// client: add a header to every request
val auth: CWrap = { req, next ->
    req.headers.set("Authorization", "Bearer $token")
    next(req)
}
CK.init(CK.Config(wrappers = Init.Wrappers(auth), cookieJar = CookieJar()))
```

```kotlin
// server: authenticate and add ctx.user (typed from `ctx { user: UserData }` in init.comat)
val auth: SWrap<Init.AuthCtx> = { req, next ->
    val user = verifySession(req.cookie("session"))
    if (user == null) {
        Init.s401(Types.ApiError("unauthorized", "login required"))
    } else {
        next(req.withCtx(Init.AuthCtx(user)))
    }
}
s.init(Init.Wrappers(auth))
```

```kotlin
// server: issue the session cookie (declared in init.comat; the endpoint has `cookie on`)
S.Reply.of<UserPostLogin.Response>(UserPostLogin.S200(UserPostLogin.S200Res(uid)))
    .withCookie(comatype.CookieValue.of(token).maxAge(3600))
```

A wrapper missing from `Init.Wrappers` is a compile error.

### Cache

Caching is declared in the `.comat` file, once, for the client and the server (GET and QUERY endpoints only):

```comat
// comatfiles/user/(noauth)/get_ping.comat  ->  GET /user/ping
s200 {
    ok: bool,
}

cache 60000          // cache the response in memory for 60 seconds
```

| Declaration | Meaning |
|---|---|
| (none) | no caching |
| `cache off` | never cache |
| `cache 5000` | in memory for 5000 ms (client and server) |
| `cache 5000 cookie` | in a cookie for 5000 ms (client only) |

- The server looks the cache up before the wrappers, with the exact request (method, path, query, all headers, body) as the key.
- The client looks it up just before the network call, with the method, URL, body and the request headers declared in the `.comat`.
- Only 2xx responses without `Set-Cookie` are cached. `cache` in `defaults.comat` or `init.comat` is ignored with a warning.
```kotlin
CK.clearCache()   // drop the client cache, for example on logout
```
