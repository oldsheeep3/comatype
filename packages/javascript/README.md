# @comatype/javascript

Comatype runtime for JavaScript: the `fetch` client `c` and the server `s`, with the same validation as the TypeScript runtime. Works on Node, Bun, Deno and Cloudflare Workers. Plain ES modules with `.d.ts` declarations: types show up in your editor without TypeScript.

[npm](https://www.npmjs.com/package/@comatype/javascript) · [Documentation](https://comatype.sheeplab.net) · [GitHub](https://github.com/oldsheeep3/comatype)

> Comatype: write an API once in `.comat` files, get types, validation, a client and a server in ten languages.
> This package is the **JavaScript** runtime that the generated code depends on.

## How to use

### Install

```bash
npm install @comatype/javascript      # or: pnpm add @comatype/javascript / yarn add @comatype/javascript
```

Node 20 or later. Generated code goes to `<root>/comatype/` by default: a `.js` file (the values) and a `.d.ts` file (the types) for each `.comat` file. If you use TypeScript, use [`@comatype/typescript`](https://www.npmjs.com/package/@comatype/typescript) and `--lang ts` instead.

The `comatype` command (parser, checker and generators) is separate from the runtime:

```bash
curl -fsSL https://raw.githubusercontent.com/oldsheeep3/comatype/main/install.sh | sh
```

This downloads the prebuilt `comatype` command (and its short alias `comat`) for macOS (arm64, x64) and Linux (x64, arm64) from the [latest release](https://github.com/oldsheeep3/comatype/releases/latest); no Rust toolchain needed. On Windows, download `comatype-x86_64-pc-windows-msvc.zip` from the release page. To build it from source instead: `cargo install --git https://github.com/oldsheeep3/comatype comatype-cli`.

### Import

```js
import { c } from '@comatype/javascript'                 // client
import { s } from '@comatype/javascript'                 // server
import { serve } from '@comatype/javascript/node'        // start the server on Node's http

// generated code: one module per .comat file (`[id]` becomes `__id`). Relative imports need the `.js` extension
import { path, s200, s404 } from './comatype/user/put__id.js'
// or everything of the endpoint under one name (path, endpoint, s200, ...)
import user_put__id from './comatype/user/put__id.js'
```

### Format / Lint

Generated files start with `// Code generated by comatype generate. DO NOT EDIT.` Exclude the directory from your linter and formatter, and regenerate instead of editing.

```jsonc
// biome.json
{ "files": { "includes": ["**", "!comatype"] } }
```

```js
// eslint.config.js
export default [{ ignores: ['comatype/**'] }]
```

```text
# .prettierignore
comatype/
```

To have the editor check your code against the generated types, turn on `checkJs` in `jsconfig.json` (`{ "compilerOptions": { "checkJs": true, "module": "NodeNext" } }`).

### Check

```bash
comatype check                  # check every .comat file; prints [error] / [warn] / [info] lines, exits 1 on errors
comatype check cache            # only one topic: cache, path, wrap, cookie, status, import, type
comatype endpoints -g           # list the endpoints, grouped by wrapper chain
comatype generate --lang js # generate the code (js only)
```

Run `comatype check` in CI so that a broken `.comat` never reaches the generated code.

### init.comat

`init.comat` holds the settings of the whole project. Put exactly one directly under `comatDir`.

```comat
// comatfiles/init.comat
import UserData from ../types/UserData.comat
import ApiError from ../types/common.comat

// The base url of every endpoint. Override it at run time with the COMATYPE_BASE_URL environment variable
baseUrl https://api.example.com

// The cookie the server issues (for `cookie on` endpoints)
cookie session {
    httpOnly: true,
    secure: true,
    sameSite: lax,
}

// A wrapper: what it adds to `ctx`, and the statuses it can return. You implement it in JavaScript
wrapper auth {
    ctx {
        user: UserData,
    }
    s401 ApiError
}
```

### comatfiles

A `.comat` file is one endpoint. Its method and path come from where the file is and what it is called.

```text
comatfiles/
├─ init.comat               baseUrl, cookie, wrapper declarations (exactly one)
├─ defaults.comat           defaults for this directory and below: wrap, headers, shared statuses
├─ post_user.comat          POST /user
└─ user/
   ├─ [id]/put.comat        PUT /user/:id        ([id] is a dynamic segment)
   ├─ (noauth)/             a group: not part of the path
   │  ├─ defaults.comat     wrap auth off
   │  ├─ post_login.comat   POST /user/login
   │  └─ get_ping.comat     GET /user/ping
   └─ get.comat             GET /user
types/                      types shared by endpoints (outside comatDir)
```

`comatype.config.json` says where `comatfiles` is and what to generate:

```json
{
  "$schema": "https://raw.githubusercontent.com/oldsheeep3/comatype/main/schema/comatype.config.schema.json",
  "services": {
    "api": {
      "comatDir": "./comatfiles",
      "targets": [{ "lang": "js", "role": "client", "root": "./web" }]
    }
  }
}
```

See the [syntax reference](https://comatype.sheeplab.net/language/endpoint/) for `params`, `search`, `body`, headers, status codes and `path`.

## Example

### ComatFiles

```comat
// types/UserData.comat
UserData {
    name: string,
    email: email,
    phone: phone,
    uid: uuidv4,
}
```

```comat
// comatfiles/user/[id]/put.comat  ->  PUT /user/:id
import UserData from ../../../types/UserData.comat
import ApiError from ../../../types/common.comat

params {
    id: uuidv4,
}

body UserData

s200 UserData
s404 ApiError
```

```comat
// comatfiles/defaults.comat: applies to every endpoint below
import ApiError from ../types/common.comat

wrap auth        // the wrapper declared in init.comat
cookie on        // send and receive the session cookie
s500 ApiError    // every endpoint can answer 500
```

```comat
// comatfiles/user/(noauth)/defaults.comat: this group needs no login
wrap auth off
```

```comat
// comatfiles/user/(noauth)/post_login.comat  ->  POST /user/login
import ApiError from ../../../types/common.comat

body {
    email: email,
    password: string,
}

s200 {
    uid: uuidv4,
}
// the auth wrapper is off in this group, so declare the 401 yourself
s401 ApiError
```

Generate the JavaScript code with `comatype generate --lang js`.

### Client

```js
import { c } from '@comatype/javascript'
import { path, s200, s404 } from './comatype/user/put__id.js'

const res = await c.put(path, { params: { id }, body: user }, s200, s404)

if (res.status === 200) res.data   // the user
if (res.status === 404) res.error  // { code, message }
```

- The result has the `status` you passed; check it. 2xx is `data`, everything else is `error`.
- A status you did not pass throws `UnexpectedStatusError`. Invalid input throws `ValidationError` **before** any network call. Without TypeScript, this validation is what protects you at run time.
- Request headers are not arguments: add them with `c.init({ headers })` or `c.with({ headers })`.

### Server

```js
import { s } from '@comatype/javascript'
import { serve } from '@comatype/javascript/node'
import { path, s200, s404 } from './comatype/user/put__id.js'

s.put(path, (req) => {
  // req.params.id, req.body: validated
  const user = db.update(req.params.id, req.body)
  if (!user) return s404({ error: { code: 'not_found', message: 'user not found' } })
  return s200({ data: user, headers: { 'X-Resource-Version': 'v2' } })
})

await serve({ port: 3000, server: s })
```

A request that does not match the `.comat` is answered with 400 before your handler runs. `s.handle(request)` takes a Fetch API `Request` (Bun, Deno, Workers, tests); `nodeListener(s)` plugs into `http.createServer`.

### Wrapper & Cookie

A wrapper wraps the request and the response: authentication, headers, logging. Declare it in `init.comat`, enable it with `wrap auth` in a `defaults.comat` or in an endpoint, and implement it in JavaScript.

```js
// client: add a header to every request
import { c, createCookieJar } from '@comatype/javascript'

const auth = async (req, next) => {
  req.headers.authorization = `Bearer ${token}`
  return next(req)
}
c.init({ wrappers: { auth }, cookie: { jar: createCookieJar() } })   // a jar for environments without cookies (Node)
```

```js
// server: authenticate and add `ctx.user` (from `ctx { user: UserData }` in init.comat)
import { s401 } from './comatype/init.js'

export const auth = async (req, next) => {
  const user = db.bySession(req.cookies.session)
  if (!user) return s401({ error: { code: 'unauthorized', message: 'login required' } })
  return next({ ...req, ctx: { ...req.ctx, user } })
}
s.init({ wrappers: { auth } })
```

```js
// server: issue the session cookie (declared in init.comat; the endpoint has `cookie on`)
return s200({ data: { uid }, cookie: { session: { value: token, maxAge: 3600 } } })
```

### Cache

Caching is declared in the `.comat` file, once, for the client and the server (GET and QUERY endpoints only):

```comat
// comatfiles/user/(noauth)/get_ping.comat  ->  GET /user/ping
s200 {
    ok: bool,
}

cache 60000          // cache the response in memory for 60 seconds
```

| Declaration | Meaning |
|---|---|
| (none) | no caching |
| `cache off` | never cache |
| `cache 5000` | in memory for 5000 ms (client and server) |
| `cache 5000 cookie` | in a cookie for 5000 ms (client only) |

- The server looks the cache up before the wrappers, with the exact request (method, path, query, all headers, body) as the key.
- The client looks it up just before the network call, with the method, URL, body and the request headers declared in the `.comat`.
- Only 2xx responses without `Set-Cookie` are cached. `cache` in `defaults.comat` or `init.comat` is ignored with a warning.
```js
c.clearCache()   // drop the client cache, for example on logout
```
